# Sori Studio(소리 스튜디오) 기능 설계서 - 로컬 오픈소스 TTS 허브 + 스튜디오 (v0.4, 2026-11-17)

> 상태: **v0.4 - 구현 기준판.** 화면 설계(`design/design.md` 13절)에서 돌아온 11개를 반영했어요(아래 "v0.4 에서 바뀐 것"). 이름은 **sori-studio**(앱 표기 "Sori Studio(소리 스튜디오)", 저장소 이름 sori-studio)로 정했어요.
> 처음 지시(2026-11-17): voicestudio(debpalash/VoiceStudio)의 UI/UX 경험을 참고해 **오픈소스용 스튜디오**를 낸다. **화면 디자인보다 기능 먼저.**
> 엔진 근거: 모두보이스의 한국어 TTS 벤치(oh-my-tts, 2026-11-16 측정 + 사람 평가)와 Sori Studio 스팟 시험(2026-11-17). 엔진마다 숫자와 날짜는 `engines/<id>/recipe.yaml` 의 `measured`·`human_eval` 칸에 있어요.

## 설계 결정
1. **로컬 전용·무료**: 계정·키·서버 없이 내 PC 에서 돌아요. 원격·유료 TTS API 는 기본으로 넣지 않아요(제3자 플러그인 자리를 열지는 열린 질문 5).
2. **제품의 중심은 허브**예요: 로컬에서 돌아가는 여러 오픈소스 TTS 를 **내려받고 묶어 주는 것**. 스튜디오는 그 위에 얹는 층이에요.
3. **Supertonic-3 은 MVP 기본 엔진**이에요(GPU 없이 CPU 로 도는 엔진).
4. **모델 라이선스 처리 원칙**(4.11)
   - 가중치는 설치본에 넣지 않고, 사용자가 고를 때 공식 출처에서 받게 해요(재배포하지 않음).
   - 받기 전에 라이선스 이름·요약·원문을 보여 주고 동의를 받아요.
   - OpenRAIL 계열은 용도 제한 조항을 그대로 알려요.
   - 개발 중단(저장소 보관)은 라이선스가 아니라 **유지보수 위험**으로 따로 표시하고, 보관 저장소 주소도 적어요.
   - **추천은 측정·사람 평가로만 하고 라이선스와 섞지 않아요.**
5. **이름은 sori-studio**예요(8.1). 만든 곳은 About·README 의 "Made by ModuVoice" 한 줄뿐이고, 앱 안에 서비스 연결·광고가 없어요.
6. **저장소는 `github.com/moduvoice/sori-studio`**.
7. **첫 판 화면은 한국어**, 다국어는 나중에 더해요. 그래서 화면 문구는 처음부터 언어 표(`ko.json`)로 빼 두었어요.
8. **라이선스 Apache-2.0, 첫 플랫폼 Windows x64 + Electron**. 리눅스·macOS 는 같은 화면을 브라우저(serve 모드)·Electron 으로.
9. **카탈로그에는 32GB GPU(RTX 5090 급)에서 도는 엔진만** 올려요. 리눅스 전용 엔진은 Windows 에서 WSL2 로 연결해요.

## 0. 한눈에

**한 줄 정의**: Sori Studio 는 한국어로 직접 시험한 오픈소스 TTS 를 **내 PC 에 골라 받아 한곳에서 돌리는 로컬 허브**이고, 그 위에서 **대본을 완성 음성으로 만드는 스튜디오**까지 함께 줘요. 비유하면 "TTS 판 Ollama + 한국어 대본 스튜디오"예요(Ollama 는 LLM 을 받고·돌리고·API 로 내주는 로컬 도구).

**핵심 기능 묶음**
1. **허브 - 모델 카탈로그**: 엔진마다 우리 벤치 측정·사람 평가·라이선스·장치(NVIDIA·CPU·Mac)·유지보수 상태를 한 장에 보여 줘요.
2. **허브 - 설치·실행 관리**: "이 PC 에서 돌아가는 모델" 표시, 원클릭 설치(엔진마다 따로 만든 파이썬 환경), 디스크·버전 관리, 엔진 상태 감시·자동 재시작, 공통 로컬 API(OpenAI 호환).
3. **허브 - 열린 엔진 규약**: 어댑터 한 벌을 oh-my-tts 벤치와 함께 쓰고, 커뮤니티가 새 엔진을 PR 로 올려요.
4. **스튜디오**: 한국어 글 다듬기 + 공통 대본 표기를 엔진별 문법으로 번역, 줄 단위 대본·테이크·일괄 생성·내보내기, 블라인드 비교, 받아쓰기(ASR) 품질 점검.
5. **LLM 도우미**(로컬 우선, 선택): 대본 정리·연기 제안부터.

**MVP(첫 공개)**: "이 PC 에서 돌아가는 한국어 TTS 를 원클릭으로 받아, 대본 한 편을 끝까지 만든다."
- P0(없으면 공개 안 함): Windows(NVIDIA·CPU) 서명 설치본, 허브(카탈로그·이 PC 판정·원클릭 설치·라이선스 동의·디스크·버전 고정·상태 감시·자가 시험), 엔진 4개(Qwen3-TTS·VoxCPM2·CosyVoice3·Supertonic-3), 스튜디오 기본(한국어 다듬기·대본 에디터·테이크·일괄 생성·내보내기).
- P1(넣으면 좋고, 늦으면 다음 판으로): 공통 로컬 API, 로컬 LLM 연결(대본 정리·연기 제안), 간단 비교, serve 모드, macOS.

**배포 형태 추천**: 허브 서버(파이썬) + 웹 화면 한 벌을 Electron 껍데기로 감싸 배포해요. 같은 허브를 serve 모드로 브라우저·다른 PC·서버에서도 쓸 수 있게 해요. 앱 라이선스는 Apache-2.0, 텔레메트리 없음, 설치 뒤 오프라인 동작.

**남은 열린 질문**(12절): 코드 서명 방법·비용(12-8, 첫 공개 전 필수, 돈이 드는 일), 상표·앱스토어 이름 확인(12-2), 국내 AI 생성물 표시 규정(12-13). 나머지는 추천대로 진행해요.

## 1. 목적과 원칙

### 1.1 목적
- 2026년에 한국어가 되는 강한 오픈소스 TTS 가 많이 나왔지만, 엔진마다 설치법·파이썬·CUDA·문법이 달라 하나 깔기도 어려워요. 우리 벤치에서도 공식 설치법이 그대로 안 된 엔진이 두 개 있었어요(ZONOS3-Mini·Scenema). **그 수고를 대신해 주는 허브**를 오픈소스로 내요.
- 우리가 가진 것을 공개 도구로 돌려줘요:
  - oh-my-tts 벤치(한국어 엔진 10개 실측·사람 평가)
  - 운영하며 쌓은 한국어 글 다듬기(숫자 읽기·발음 보정)
  - 줄 단위 대본 에디터 경험
- 우리 서비스를 파는 도구가 아니에요. 앱 안에 회사 서비스로 가는 연결이 없고, 만든 곳은 About 의 "Made by ModuVoice" 한 줄로만 밝혀요.
- 한국어가 먼저지만, 엔진이 지원하는 다른 언어도 그대로 써요.

### 1.2 원칙
1. **상업 서비스 연결 없음**: 우리 서비스를 포함해 어떤 유료 API 도 기본 탑재하지 않아요. 모든 기능이 계정·키 없이 로컬에서 돌아가요.
2. **허브가 먼저, 스튜디오는 그 위**: 스튜디오는 허브 공통 API 를 쓰는 첫 번째 앱이에요. 허브만으로도(다른 앱·에이전트가 불러도) 쓸모가 있어야 해요.
3. **첫 실행이 되는 것이 기능보다 먼저**: voicestudio 이슈 1,494개 중 제목에 'backend'(서버 연결 안 됨·죽음)가 들어간 것이 369개(약 25%), 설치가 135개(약 9%)예요. 설치·실행·감시를 먼저 지켜요.
4. **로컬 우선·오프라인**: 설치가 끝나면 인터넷 없이 돌아가요. 네트워크는 사용자가 누른 일(모델 받기, 업데이트 확인)에만 써요.
5. **측정한 것만 말한다**: 추천은 우리 벤치·사람 평가 근거로 하고 라이선스와 섞지 않아요. 확인 못 한 것은 "미검증"으로 보여 줘요. 자연스러움은 사람 귀로 판단해요(기계 자연스러움 점수가 기계음 같은 Supertonic-3 을 1등으로 매긴 적이 있어요).
6. **재배포하지 않는다**: 모델 가중치·엔진 코드를 설치본에 넣지 않고, 사용자가 공식 출처에서 받게 해요. 우리가 내는 것은 "어떻게 받고 돌리는지"(레시피·어댑터)뿐이에요.
7. **LLM 은 로컬 우선·선택**: LLM 이 없으면 규칙으로 돌아가고, 있으면 더 편해져요. LLM 은 제안만 해요.
8. **보이는 글과 읽는 글을 나눈다**: 사용자의 대본·자막은 그대로 두고, 엔진에 보내는 글만 다듬어요.
9. **작게 유지**: 엔진은 "맡을 일"이 있을 때만 들이고, 범위는 "TTS 허브 + 대본 → 음성"이에요.
10. **투명함·동의**: 라이선스·네트워크 호출·디스크 사용을 미리 보여 주고, 목소리 복제는 동의를 기록해요.

### 1.3 대상 사용자
| 사용자 | 하려는 일 | 꼭 필요한 기능 |
|---|---|---|
| **크리에이터**(유튜브 나레이션, 오디오북, 팟캐스트, 웹툰·오디오 드라마) | 대본을 넣고 여러 인물 목소리로 완성 파일을 뽑음 | 쉬운 설치, 이 PC 에 맞는 엔진 추천, 캐릭터별 목소리, 줄 다시 만들기, 내보내기 |
| **개발자** | 다른 앱·에이전트·스크립트에서 로컬 TTS 부르기 | 공통 로컬 API(OpenAI 호환), 명령줄, 다른 PC 의 허브, 어댑터 규약 |
| **연구자·기여자** | 한국어 TTS 비교, 새 엔진 붙이기 | 비교 모드, 기계 점수, 재현 정보(엔진 판·씨앗), 엔진 PR 규약·측정 틀 |

### 1.4 하지 않을 것
- **상업 서비스·유료 TTS API 기본 탑재**(우리 서비스 포함).
- **모델 가중치·엔진 코드 재배포**(우리 서버 미러 포함).
- 영상 더빙 파이프라인 전체, 받아쓰기 위젯·통화·휴대폰 앱(운영체제마다 끝없이 손이 가는 영역).
- 호스팅 서비스(스튜디오를 우리 서버에서 남에게 서비스하기).
- 텔레메트리(익명 사용 통계 포함).
- 실존 인물 목소리 꾸러미.
- 처음부터 모델 학습, 음악 생성·범용 오디오 편집(DAW).

## 3. 전체 구조
```
┌─ 스튜디오 층(웹 화면) ─────────────────────────────────────────┐
│ 프로젝트 · 대본 에디터 · 목소리 · 비교 · 품질 점검 · LLM 도우미   │
└───────────────┬──────────────────────────────────────────────┘
                │ 허브 공통 API(스튜디오도 바깥 앱도 같은 것)
┌─ 허브 층(로컬 서버, 파이썬) ───────────────────────────────────┐
│ 카탈로그 · 이 PC 판정 · 설치기 · 디스크 · 버전 · 감시기          │
│ 한국어 글 다듬기 · 공통 표기 번역기 · 작업 큐 · 공통 로컬 API    │
└──────┬──────────────────┬──────────────────────┬─────────────┘
  엔진 일꾼(파이썬)     엔진 일꾼(서버형)       엔진 일꾼(네이티브)
  엔진마다 uv 환경      SGLang-Omni 등         ONNX·GGUF 실행 파일
  (Qwen3·VoxCPM2·…)    (Drama-3·ZONOS3)       (Supertonic 등)
       ↑ 가중치·엔진 코드는 사용자가 공식 출처(HF·GitHub·PyPI)에서 받음
```
- **엔진 일꾼은 허브와 다른 프로세스**예요. 엔진이 죽어도 허브와 화면은 살아 있고, 엔진마다 다른 PyTorch 판을 쓸 수 있어요. 우리 벤치에서 torch 로 직접 돌린 엔진 6개가 torch 판 네 가지(2.7·2.9·2.11·2.15)와 CUDA 묶음 세 가지(cu128·cu130·cu132)로 갈렸어요(`tmp/res/*.man.json` runtime). 한 환경에 모을 수 없어요.
- 다른 앱·에이전트도 같은 공통 API 로 허브를 불러요(4.9).
- 허브의 중심은 TTS 지만, 품질 점검용 ASR 과 도우미 LLM 도 같은 카탈로그·설치 방식으로 받아요(역할 `tts`·`asr`·`llm`).

- **화면**: 카드 목록 + 거르기. "이 PC 에서 돌아가는 것만"이 기본으로 켜져 있고, 맡을 일·CPU 만으로도 거를 수 있어요("상업 사용 가능만" 거르기는 두지 않아요 - 오픈소스 허브라서 라이선스는 배지·동의로 알려요). 카드의 "측정 근거 보기"는 **sori-studio 저장소 안의 측정 페이지**로 가요(회사 블로그로 보내지 않아요, 8.2).
- **원본**: 저장소의 엔진 폴더마다 있는 `recipe.yaml` 이 원본이고, 카탈로그는 앱과 함께 들어가요(가중치는 안 들어감). 측정 칸은 oh-my-tts 결과에서 자동으로 채워요.

| 내 목소리 | VoxCPM2(전사를 넣을 때 닮음 0.81) | CosyVoice3(전사 없이) | 전사는 손으로 넣음(5.8) |
| GPU 없음 | Supertonic-3 | - | |

### 4.4 원클릭 설치와 격리 방식
**격리 방식 비교**(엔진마다 파이썬·CUDA·의존성이 부딪히는 문제를 어떻게 나눌지)
| 방식 | 장점 | 단점 | 판단 |
|---|---|---|---|
| **엔진마다 uv 가상 환경** | 빠름, 잠금 파일로 같은 환경을 다시 만들 수 있음, 관리자 권한 불필요, Windows·맥·리눅스가 같은 방식, 캐시 공유로 같은 패키지를 한 번만 받음 | ffmpeg 같은 시스템 프로그램은 따로 챙겨야 함, 빌드가 필요한 패키지(flash-attn 등)는 미리 만든 휠이 있어야 함 | **기본**(voicestudio·TTS-WebUI 도 같은 길, 우리 벤치도 엔진별 환경) |
| conda | CUDA·ffmpeg 같은 바이너리도 패키지로 받음 | 느리고 큼, 일반 사용자 설치 경험이 나쁨, 기본 채널 약관 문제가 알려져 있음(쓴다면 conda-forge, 조건 확인 필요) | **쓰지 않음** |
| 컨테이너(도커) | 가장 단단한 격리, 도커가 공식인 엔진은 그대로 씀 | Windows·맥은 Docker Desktop 이 필요(무겁고, 조직 사용 약관 확인 필요), GPU 연결 설정이 어렵고 맥 GPU 는 안 됨 | **서버·고급 선택지**(리눅스 serve 모드, 도커만 공식인 엔진 - Scenema) |
| 네이티브 실행 파일(ONNX·GGUF) | 파이썬이 없고 가장 가벼움 | 엔진마다 포트가 있어야 함 | **있으면 우선**(Supertonic ONNX, 이후 GGUF 포트) |

**추천: 엔진마다 uv 환경을 기본으로 하고, 네이티브 포트가 있으면 그것을 우선, 도커는 서버·고급 선택지로.** 크리에이터 PC(주로 Windows)에서 도커·conda 는 설치 장벽이 너무 커요. 같은 길을 간 voicestudio 의 설치 문제는 주로 서명·드라이버·엔진 결함에서 왔고, 격리 방식 자체는 아니었어요.

**세부**
- **허브 자체 파이썬**: 앱 전용이고 운영체제 파이썬을 건드리지 않아요.
  - Windows 는 python.org 공식 배포본을 먼저 검토해요. 공식 페이지는 Windows 설치 파일과 릴리스마다 만드는 모든 바이너리에 PSF(Python Software Foundation)의 Authenticode 서명을 붙인다고 적었어요([python.org](https://www.python.org/downloads/windows/)). 다만 임베드용 zip 의 python.exe 도 서명됐는지는 확인이 필요해요.
  - 이유: voicestudio 에서 서명 없는 python.exe 를 Windows 가 막아 "spawn UNKNOWN" 으로 실패한 이슈가 아직 열려 있어요(#3635 등).
  - 맥·리눅스는 uv 가 받는 독립 파이썬을 써요.
- **엔진 환경**
  - 엔진마다 uv 가상 환경, 플랫폼별 잠금 파일을 두고, torch 판은 그 엔진 레시피가 정해요. 같은 판끼리는 uv 캐시를 함께 써요.
  - 빌드가 필요한 패키지는 쓰지 않아요. 미리 만든 휠만 쓰고, 없으면 기본 어텐션(sdpa)으로 돌려요(우리 Qwen3 경험).
- **시스템 프로그램**(ffmpeg 등): 허브가 고정판을 공식 출처에서 받아 엔진 환경의 실행 경로에만 넣어요.
- **서버형 엔진**(SGLang-Omni 계열): 도커가 아니라 같은 uv 환경 안에 소스로 설치해 띄워요(우리 벤치에서 ZONOS3·Drama-3 를 이렇게 띄웠어요).
- **설치 단계**: 단계마다 체크포인트가 있어 실패하면 그 단계부터 다시 해요.
  1. 계획 미리 보기(받을 양·디스크·예상 시간·라이선스)
  2. 라이선스 동의(4.11)
  3. 파이썬 환경
  4. 패키지(잠금 파일 그대로, 해시 검증)
  5. 가중치(공식 출처의 고정한 커밋, 이어받기·해시 검증)
  6. **자가 시험**(한국어 3문장)
  7. 완료
- **자가 시험을 통과해야 "설치됨"**이에요. voicestudio 에서 "설치 성공이라더니 생성이 전부 실패"(CosyVoice 3, #2096)한 일을 막으려는 거예요.

**실패 분류와 고치기**
| 분류 | 예 | 허브가 하는 일 |
|---|---|---|
| 디스크 | 공간 부족 | 필요한 양·지울 수 있는 것 제안(4.6), 다른 드라이브 고르기 |
| 네트워크 | 끊김·느림·회사망 차단 | 이어받기, 사용자가 고른 미러·프록시 |
| 드라이버·장치 | 드라이버 오래됨, 새 GPU 세대를 모르는 판 | 필요한 드라이버 판 안내, CPU 엔진 제안 |
| 의존성 | 휠 없음, 빌드 실패 | 검증된 휠만 쓰는 레시피, 선택 가속 끄기 |
| 권한·보안 | 백신·SmartScreen 이 실행 파일을 막음 | 서명된 런타임, 예외 안내 |

| 엔진 자체 | 공식 설치법이 안 됨(ZONOS3 pip, Scenema Dockerfile) | 우리가 고친 레시피(검증 커밋 고정) |
| 알 수 없음 | | 로그 묶음(키·경로 가림) + 미리 채운 GitHub 이슈 링크 |

### 4.5 하드웨어 자동 감지와 "이 PC 에서 돌아가는 모델"
- **읽는 것**: 운영체제·CPU 종류(x64/ARM)·코어·RAM, GPU 종류·이름·메모리·드라이버 판·세대(NVIDIA 는 세대 번호 - Blackwell 은 CUDA 12.8 이상 torch 필요), Apple 칩·통합 메모리, 드라이브별 빈 공간.
- **판정**: 엔진마다 여섯 가지 중 하나로 보여 줘요(v0.4).
  | 판정 | 언제 | 색·표시 |
  |---|---|---|
  | GPU 로 잘 돌아요 | GPU 메모리 ≥ 측정 최대 × 1.15 | 초록 |
  | CPU 로 잘 돌아요 | CPU 전용 엔진(Supertonic-3, 소리 1초에 0.15초) | 초록 |
  | CPU 로 느리게 돌아요(예상 속도) | GPU 엔진인데 GPU 가 모자라 CPU 로만 됨 | 노랑 |
  | 메모리가 빠듯해요 | 측정 최대 ≤ 메모리 < 측정 최대 × 1.15 | 노랑, "그래도 설치" 가능 |
  | 안 돌아요(이유) | 메모리 부족, 맥 미지원 등 | 회색 |
  | 미검증 | 그 장치의 측정이 없음(Mac 전부, Qwen3-TTS 한 판 메모리) | 회색 점선, "설치하면 자가 시험으로 확인해요" |
  - 근거는 측정 최대 메모리 + 여유(처음 값 15%, 추정 - 시험으로 조정)예요.
- **두 번 판정**: 설치 전에는 카탈로그 값으로, 설치 뒤에는 자가 시험 실측으로 고쳐요. 실측은 그 PC 기록으로 남겨 다음 판정에 써요.
- GPU 가 여러 개면 고를 수 있어요. "그래도 설치"(경고와 함께)도 허용해요.

### 4.6 디스크 관리
- **보이는 것**: 엔진별(환경·가중치·캐시) 용량, 전체 용량, 드라이브 빈 공간, 프로젝트 테이크 용량.
- **지우기**: 엔진 통째, 환경만(가중치는 남겨 다시 설치가 빠름), 가중치만, 캐시(미리 듣기·임시 파일). 확인 창에 되찾는 용량을 보여 줘요.
- **위치**: 첫 실행에 모델 폴더(드라이브)를 고르고, 나중에 옮길 수 있어요. voicestudio 에서 반응이 많았던 요청("모델을 원하는 폴더에" #64)과 실패("기본 드라이브가 아니면 설치 안 됨" #938)를 반영했어요.
- **공유**: uv 캐시(같은 휠은 한 번만), HF 캐시(두 엔진이 같은 가중치를 쓰면 한 번만).
- 설치 전에 공간을 점검하고, 모자라면 지울 후보를 제안해요. 지운 엔진의 찌꺼기 파일도 찾아 줘요.

### 4.7 업데이트·버전 고정
- **앱**: 서명된 업데이트예요. 하루 한 번 판 번호만 확인하고(첫 실행에 켤지 묻고, 기본 켬 추천), 설치는 사용자가 확인해야 해요.
- **카탈로그**: 앱과 함께 들어가요. "새 엔진 확인"을 누르면 sori-studio 저장소의 카탈로그 파일만 받고, 해시나 서명으로 검증해요.
- **엔진**
  - 레시피 판(코드 커밋·가중치 커밋·잠금 파일)으로 고정하고, "main" 같은 움직이는 판은 쓰지 않아요.
  - 새 레시피가 나오면 "업데이트 있음"을 표시해요. 새 환경을 옆에 만들고 자가 시험 + 내 줄 몇 개로 전후 비교를 한 뒤 바꿔요(v1).
  - 이전 판은 사용자가 확인할 때까지 남겨 되돌릴 수 있어요(디스크가 허락하면).
- **재현**: 프로젝트의 테이크마다 엔진 판을 기록해 같은 소리를 다시 만들 수 있어요.
- **공식 출처가 바뀌거나 사라질 때**(저장소 이전·삭제·게이트화): 카탈로그에 "출처 바뀜/사라짐"을 표시해요. 이미 받은 사용자는 계속 쓸 수 있고, 우리는 미러하지 않아요(4.11).

### 4.8 엔진 상태 감시·자동 재시작
voicestudio 이슈의 약 25% 가 "로컬 백엔드에 닿을 수 없음"·"백엔드 죽음"이었어요. 허브는 **두 겹으로 감시**해요.

**겹 1 - 허브 서버(껍데기가 감시)**
- 시작을 단계로 보여 줘요: 파이썬 확인 → 서버 켜는 중 → 엔진 목록 읽는 중 → 준비. 단계마다 시간 한도가 있고, **뭉뚱그린 "닿을 수 없음" 대신 단계와 원인**을 보여 줘요.
  - 포트 사용 중이면: 다른 허브가 이미 켜져 있을 때 그쪽에 붙어요.
  - 파이썬 실행이 막히면: 백신·서명 안내.
  - 의존성이 깨지면: 잠금 파일과 다를 때 "고치기".
  - 디스크가 가득 차면: 정리 안내.
  - 알 수 없으면: 로그를 보여 줘요.
- 한 컴퓨터에 허브는 하나만 켜요(잠금 파일).
- 허브가 죽으면 껍데기가 자동으로 다시 켜요(10분에 3번까지). 그래도 안 되면 **복구 모드**(로그 보기·환경 고치기·깨끗이 다시 설치)로 들어가요.

**겹 2 - 엔진 일꾼(허브가 감시)**
- **설치 상태**(v0.4): 안 받음 / 받는 중 / 멈춤(이어받기 대기) / 실패(분류·고치기) / 설치됨 / 업데이트 있음 / 출처 바뀜.
- **실행 상태**(v0.4): 켜짐 / 불러오는 중 / 쉬는 중(메모리에서 내려감) / 다시 켜는 중(자동 재시작) / 멈춤 / 죽음. 화면에 엔진별 상태·메모리·최근 오류를 보여 줘요.
- **GPU 엔진 함께 올리기**(v0.4): 측정 메모리 합 + 여유 15% 가 카드에 들어가는 만큼 함께 올리고, 넘으면 가장 오래 안 쓴 엔진부터 쉬게 해요. 8~12GB 카드는 사실상 하나씩이라, 섞인 대본은 큐가 엔진별로 묶고 "엔진을 바꿔 올리는 중" 을 보여 줘요(남은 시간에 불러오기 시간을 더함).
- **생존 확인**: 5초마다 확인해서 세 번 연달아 답이 없으면 멈춤으로 봐요.
- **시간 한도는 둘로 나눠요**:
  - 불러오기 한도: 엔진 측정 불러오기 시간 × 3, 최소 2분. CosyVoice3 는 불러오기만 106초 걸렸어요.
  - 생성 한도: 예상 소리 길이 × 이 PC 측정 RTF × 3 + 30초.
  - 이 숫자들은 처음 값이고 시험으로 조정해요. 첫 생성이 모델 받기로 시간 초과되던 voicestudio 의 문제(#1014)를 피하려는 거예요.
- **자동 재시작**: 죽거나 멈추면 다시 켜고(즉시 → 10초 → 60초), 하던 요청은 같은 씨앗으로 한 번 다시 해요. 10분에 3번 넘게 죽으면 "죽음"으로 표시하고 원인과 제안을 보여 줘요.
- **원인별 처리**
  - **GPU 메모리 부족**: 묶음을 반으로 나눠 다시 해요(우리 `gen.py` 의 `batch_split` 경험). 그래도 안 되면 작은 판·CPU 를 제안해요.
  - **드라이버 오류**: 드라이버 안내.
  - **네이티브 충돌**(접근 위반 같은 것, voicestudio #4142): 일꾼만 정리하고 허브는 살려요. "다시 설치" 제안.
- **고아 프로세스 방지**: 허브가 죽어도 엔진 일꾼이 GPU 메모리를 붙잡고 남지 않게, 프로세스 그룹(Windows 는 Job)으로 묶어 함께 정리해요.
- 한 엔진이 죽어도 다른 엔진·화면은 계속 돌아가요.

### 4.9 공통 로컬 API - 넣는다(MVP P1)
**판단**: 넣어요. 이유는 넷이에요.
- 엔진마다 공식 서버·호출 방식이 다 달라서 **한 주소로 부르게 해 주는 것이 허브의 존재 이유**예요("TTS 판 Ollama").
- 스튜디오가 이미 쓰는 API 를 문서·보안 장치와 함께 바깥에 여는 것이라 추가 작업이 작아요.
- 에이전트·음성 앱 생태계가 OpenAI 모양 TTS 주소를 그대로 받아요. voicestudio 문서에 pipecat·LiveKit·OpenAI Agents SDK 연결 예시가 있고, Speaches(MIT)도 같은 모양이에요.
- 엔진을 바꿔도 부르는 쪽 코드는 그대로예요.

| 주소 | 하는 일 | 단계 |
|---|---|---|
| `POST /v1/audio/speech` | 말 만들기(OpenAI 모양: `model` = 엔진 id, `voice` = 목소리 id, `input`, `response_format` wav·flac·pcm·mp3, `speed`, `instructions` = 연기 지시 → 공통 표기로 받아 엔진별 번역, 스트리밍) + 확장 칸(`seed`, `language`, 한국어 다듬기 끄기) | MVP P1 |
| `GET /v1/models` | 설치된 엔진 | MVP P1 |
| `GET /v1/audio/voices` | 엔진별 목소리 | MVP P1 |
| `GET /hub/engines`, `GET /hub/engines/{id}` | 카탈로그·상태·이 PC 판정 | MVP P1 |
| `POST /v1/audio/transcriptions` | 받아쓰기(점검용 ASR 이 깔려 있으면) | v1 |
| 설치·지우기 | 바깥 API 로는 열지 않음(화면에서 사용자가 확인해야 함) | - |

**보안**(로컬 HTTP 는 아무 웹 페이지나 부를 수 있어서 꼭 필요해요)
- 기본은 `127.0.0.1` 에서만 받아요.
- **모든 호출에 토큰**을 요구해요. 스튜디오는 저절로 받고, 바깥 앱은 설정 화면에서 복사해요.
- **Host 머리말 검사**: 남의 도메인을 내 PC 로 돌려 부르는 공격(DNS 재바인딩)을 막아요.
- **CORS 를 닫아 둬요**: 다른 웹 페이지가 브라우저에서 허브를 부르지 못해요.
- 같은 망에 열기는 serve 모드에서 명시적으로 켤 때만이에요(HTTPS 또는 사설망 경고).
- 크기·횟수 제한을 두고, API 로 파일 경로를 받지 않아요(소리는 바이트로 주고받음).

**호환성**
- API 판(`/v1`)을 고정하고, 오류는 OpenAI 모양으로 줘요.
- 공식 OpenAI SDK 로 계약 시험을 해요(voicestudio 도 이렇게 함).
- 명령줄(`sori-studio list`·`pull`·`rm`·`serve`·`say`·`doctor`)은 이 API 의 얇은 껍데기예요(MVP P2, v1 P1).

### 4.10 엔진 추가 규약 - 어댑터 한 벌, 커뮤니티 PR
**어댑터는 한 번만 써요.** sori-studio 저장소의 `engines/<id>/` 를 **어댑터의 원래 자리**로 삼고, oh-my-tts 벤치(`jobs/bench/gen.py`)도 같은 어댑터를 불러요. 지금 벤치 어댑터(`caps`·`load()`·`synth(text, ref, ref_text, preset, design, style, seed)`·`synth_batch()`·`synth_dialogue()`·`presets()`)를 넓혀 옮겨요. 새 엔진을 벤치로 재면 그 결과가 그대로 카탈로그의 `measured` 칸이 돼요.

**엔진 폴더**
```
engines/<id>/
  recipe.yaml    선언(아래)
  adapter.py     어댑터
  recipe/        플랫폼별 잠금 파일·서버 명령(·도커)

```

**선언 파일 `recipe.yaml`**(예시 - 칸 이름은 구현 때 확정)

**함수**
| 함수 | 하는 일 |
|---|---|
| `probe()` | 이 PC 에서 되는지(됨·느림·안 됨) + 이유 + 고치는 법. 오류 문구에 경로·키를 넣지 않음 |
| `install(plan)` / `load(device)` / `unload()` | 설치(별도 환경) / 불러오기(불러오기 한도) / 내리기(쉬면 5분 뒤 자동) |
| `health()` | 생존 확인(상태·메모리·대기 수) - 4.8 |
| `voices()` | 기본 목소리 + 샘플 |
| `synth(req)` / `synth_batch(reqs)` / `synth_dialogue()` / `stream(req)` | 만들기 / 묶어 만들기 / 여러 화자(`dialogue > 1`) / 조각 스트리밍 |

- **요청**:
  - `text`: 엔진에 보낼 글(한국어 다듬기·표기 번역을 거친 것)
  - `voice`: 기본 목소리 id / 참조 `{audio, transcript?}` / 설계 `{description}`
  - `style`: 엔진 문법으로 번역된 지시
  - 그 밖: `speed`·`seed`·`language`·`extras`
- **결과**: 모노 float32 소리 + 표본율 + 메타(`gen_secs`·`seed`·`engine_version`·`warnings`).
- **지문**: `hash(엔진 id + 판 + 목소리 + 엔진 글 + 설정 + 씨앗)`. 같은 지문이면 저장된 테이크를 다시 써요.
- **통신**: 엔진 일꾼은 내 PC 안 작은 HTTP 서버(무작위 포트 + 1회용 토큰)로 띄우고, OpenAI 호환 `/v1/audio/speech` + 확장 칸으로 말해요. 공식 서버형 엔진과 같은 길이에요(우리 벤치 `_sglomni.py`).

**커뮤니티 PR 흐름**
1. 기여자가 `engines/<id>/` 폴더를 PR 로 올려요.
2. **CI(GPU 없음)**: 선언 칸 검사(라이선스·공식 출처 칸 필수), 가짜 모델로 어댑터 규약 시험, 잠금 파일 해시 확인, 문서 링크 확인.
3. **측정**: 기여자가 "한국어 소세트"(기본 51문장 중 20문장 + 맡을 일에 맞는 기능 시험) 결과와 소리 묶음을 첨부하거나, 우리가 GPU(스팟)로 재요. 결과는 측정 페이지와 `measured` 칸으로 가요.
4. **등급**: 공식(우리 측정 + 사람 평가) / 기여자 측정 / 실험(측정 없음). 실험 등급은 기본 카탈로그에서 숨기고, 설정에서 켜면 보여요.
5. **받아들이는 기준**: 맡을 일이 있고(지금 담당 엔진보다 나은 숫자, 또는 아무도 안 맡은 일), 한국어 측정이 있고, 권리 기록·공식 출처가 있고, 자가 시험이 있고, **12개월 담당자**가 있어야 해요. "점수가 좋다"만으로는 안 들여요.
6. **보관**: 두 판 연속 담당자도 자가 시험 통과도 없으면 "보관"으로 돌려요(voicestudio 규칙).
- 엔진을 다른 프로세스로 돌리면 엔진 코드와 앱 코드의 라이선스가 섞이지 않는다고 흔히 보지만, 법률 검토는 아니에요.

### 4.11 모델 라이선스 처리와 상업 사용 경고
1. **재배포하지 않아요**: 설치본·우리 서버에 가중치·엔진 코드를 넣지 않아요. 사용자가 엔진을 고를 때 허브가 **공식 출처**(Hugging Face·ModelScope·공식 GitHub·PyPI)에서 받아요. 재배포 의무를 피하려는 거예요. 우리가 내는 것은 레시피·어댑터(우리 코드)뿐이에요. 사용자가 직접 고른 미러는 허용해요.
2. **받기 전에 동의**: 라이선스 이름, 우리 말 요약(상업·호스팅·표시 의무·금지 용도를 3~5줄로), 원문 링크를 보여 주고 동의를 받아요. 요약 옆에는 "참고용, 원문이 우선"이라고 적어요. 동의 기록(날짜·모델 판·라이선스 판)은 로컬에 남겨요.
3. **OpenRAIL 계열**(예: Supertonic-3 의 OpenRAIL-M): 용도 제한 조항을 **요약하지 않고 원문 그대로** 보여 주고 동의를 받아요.
4. **배지**: 상업 사용 가능 / 조건부(매출·표시 의무 등) / 비상업 / 미확인. **미확인은 허가가 아니에요.**
5. **내보낼 때 경고**:
   - 프로젝트에 비상업·조건부 엔진으로 만든 줄이 있으면 내보내기 화면에 표시하고, "만든 방법" 기록에 엔진과 라이선스를 남겨요.
   - 표시 의무가 있는 엔진은 그 문구를 기록에 넣어요(예: "Built with Fish Audio").
6. **유지보수 위험은 따로**: 저장소 보관·개발 중단은 라이선스 배지와 다른 **"보관됨 - 업데이트·보안 수정 없음"** 배지로 보여 주고, 보관 저장소 주소를 함께 적어요.
7. **추천과 분리**: 추천 순서는 측정·사람 평가로만 정하고, 라이선스·유지보수는 배지·경고로만 보여 줘요(4.3).
8. **게이트 모델**(약관 동의·토큰이 필요한 모델): 사용자가 공식 페이지에서 직접 동의하고 토큰을 넣게 안내해요. 같은 가중치의 비공식 사본은 기본으로 쓰지 않아요(벤치에서는 공개 사본을 썼지만, 배포 앱은 공식 경로가 원칙이에요).
9. 요약은 법률 자문이 아니에요. 라이선스는 새 엔진을 카탈로그에 올릴 때 확인해요.
10. 앱 코드는 Apache-2.0(7.4), 엔진 코드·가중치는 각자의 라이선스를 따라요.

### 4.12 원격·유료 API - 기본 탑재 없음
- 우리는 원격·유료 TTS API 를 **아무것도 기본 탑재하지 않아요**. 공식 카탈로그에도 없어요.
- 엔진 규약에 `kind: remote` 자리를 열어 제3자가 플러그인으로 붙이게 할지는 **열린 질문 5**예요.
  - 연다면: 기본 꺼짐(설정에서 "외부 엔진 허용"을 켜야 보임), "글이 외부로 나가요·유료일 수 있어요" 배지, 키는 OS 키체인, 비교 모드 등 모든 화면에서 로컬 엔진과 구분 표시.
  - 열지 않으면: 로컬 엔진과 내 서버의 허브만 써요.
- **허브-허브 연결**(내 다른 PC·서버에 띄운 같은 허브를 부르기)은 로컬 오픈소스 엔진을 쓰는 것이라 이 제한에 들지 않아요(v1).

## 5. 스튜디오 층(허브 위)
스튜디오는 허브 공통 API 만 써요. 허브의 엔진·카탈로그·감시를 그대로 이용하고, 그 위에 "대본 → 완성 음성" 작업을 얹어요.

### 5.1 한국어 글 다듬기(엔진에 보내기 전)
순서는 **보이는 글 → ① 정규화 → ② 발음 사전 → ③ 엔진별 조정 → 엔진 글**이에요. 사용자는 줄마다 "엔진에 간 글"을 펼쳐 볼 수 있어요. 이 단계는 허브에 있어서 공통 API 로 부를 때도 적용돼요(끌 수 있음).
1. **정규화**: 숫자·날짜·시간·금액·단위·전화번호·기호·영어 약어를 한글 읽기로 바꿔요(`D:\tt\common\kotext.py` 바탕).
   - 알려진 빈틈 1 - **전화번호는 자릿수로** 읽어야 해요(운영 경험: 1588-1234 를 수로 읽은 사례).
   - 알려진 빈틈 2 - 숫자+단위 결합(7조는 [칠조]).
2. **발음 사전**: 글자만으로 알 수 없는 발음(갈등→갈뜽, 1도→일또)을 **형태소 분석(Kiwi)으로 명사 토큰 전체가 표제어와 같을 때만** 바꿔요. 낱말 일부가 겹쳐 엉뚱하게 바뀌는 사고를 막으려는 거예요. 사용자 사전도 더할 수 있어요.
   - 운영 경험(`docs/pronunciation-plan.md`): **문장 전체를 소리대로 바꾸면 오히려 나빠지고**, 여꿘·사껀처럼 **드문 글자가 생기면 모델이 못 읽어요.** 그래서 모델이 틀리는 것만 고쳐요.
   - 받아쓰기로는 된소리 차이를 가릴 수 없어 사람 귀로 확인해요.
3. **엔진별 조정**: `text_frontend` 선언에 따라 켜고 꺼요. Confucius4·CosyVoice 처럼 **숫자를 영어로 읽는 엔진에는 반드시 한글로** 보내요.
- 다듬다가 실패하면 원문 그대로 보내요(다듬기 오류가 생성을 막지 않게).
- 한국어가 아닌 대본에는 쓰지 않아요(줄의 언어 칸 기준).

### 5.2 공통 대본 표기와 엔진별 번역
엔진마다 감정·비언어를 넣는 문법이 다르고, 모르는 표기를 받으면 그 글자를 소리 내 읽어요. 그래서 **대본은 공통 표기로 쓰고, 허브가 엔진별로 번역**해요.

| 공통 표기 | 뜻 | 하는 일 |
|---|---|---|
| `[쉼 0.5초]` | 쉼 | 엔진에 보내지 않고, 줄을 나눠 만든 뒤 무음을 붙임(모든 엔진 같음) |
| `[웃음]` `[한숨]` `[숨]` `[울음]` `[헐떡임]` | 비언어 | 엔진이 아는 태그로 번역(Fish `[laughs]`·`[sighs]`, Supertonic `<laugh>`·`<sigh>`·`<breath>`, CosyVoice `[breath]`). **모르는 엔진이면 빼고 줄에 표시** |
| 줄의 **연기** 칸: 고정 목록(기쁨·슬픔·화남·두려움·놀람·속삭임·차분) + 자유 글 | 감정·연기 지시 | 엔진별 자리·언어로 번역(아래 표), 못 받는 엔진은 칸을 끄고 이유 표시 |
| `{1588-1234|일오팔팔 일이삼사}` | 읽기 지정 | 엔진에는 읽기를, 화면·자막에는 원문을 씀 |
| 줄의 **캐릭터** 칸 | 화자 | 불러오기 때 `이름: 대사` 를 자동 배정 |

**연기 지시 번역 규칙(우리 측정, 2026-11-16)**
| 엔진 | 지시 자리 | 한국어 지시 | 영어 지시 | 규칙 |
|---|---|---|---|---|
| Qwen3-TTS | 대사와 따로 있는 지시 칸 | 새어 나옴 0%, 반영 14% | 반영 71% | **영어로 번역**. 참조 복제와는 같이 못 씀 → 지시를 쓰는 줄은 기본 목소리로 |
| VoxCPM2 | 대사 앞 괄호 | 전사 이어 말하기 모드: 40% 새어 나옴 / 참조만 주는 모드: 0% | 94% / 0% | 지시가 있는 줄은 **참조만 주는 복제로 바꿈**. 반영 자체는 약함(29%) |
| CosyVoice3 | instruct2 `…<|endofprompt|>` | 44% 새어 나옴 | 0% | **영어만** |
| Fish Drama-3 | 대사 앞 대괄호 | 0/64 | 0/16 | 그대로(한국어 가능) |
| Scenema | `<action>` | 15% 새어 나옴 | 0% | **영어만** |
| Supertonic·Confucius4·ZONOS3 | 없음 | - | - | 칸 끔. Confucius4 는 "감정이 담긴 참조 클립"으로 대신(참조의 감정을 따라감) |

- 번역은 **고정 표**(감정 7종 ↔ 영어 문구, 벤치의 `STYLE_EN`)가 기본이에요. 자유 글 지시는 LLM 이 있으면 영어로 옮기고, 없으면 고정 목록만 써요.
- **태그는 "확인됨/미확인"을 따로 보여 줘요**. 소리 사건 검출로 확실히 잡힌 것은 Fish 의 한숨뿐이었어요. 나머지는 "귀로 확인 필요"로 표시해요.

### 5.3 작업 공간
- **프로젝트 = 폴더 하나**(사람이 읽을 수 있는 JSON + 소리 파일)라 옮기기·백업·git 이 쉬워요. 자동 저장, 되돌리기·다시 하기, 묶어 내보내기(zip)·가져오기를 지원해요.
```
내프로젝트/
  project.json      대본 줄·캐릭터·설정·판
  takes/<줄>/<테이크>.wav (+ 만든 방법 .json)
  refs/             참조 클립 사본
  exports/
```
- **캐릭터** = 엔진 + 목소리 + 기본 연기·속도·음량을 묶은 것이에요. 줄은 캐릭터를 골라요. 캐릭터의 엔진·목소리를 바꾸면 그 캐릭터의 모든 줄이 "다시 만들어야 함"이 되고, 한 번에 다시 만들 수 있어요.
- **대본 에디터**(줄 단위 대본 에디터 경험)
  - 줄마다 캐릭터·대사(보이는 글)·읽기 지정·연기·비언어·속도·뒤 쉼·그 줄만 엔진 바꾸기·상태(안 만듦 / 기다림 / 만드는 중 / 만듦 / 오래됨 / 실패 / 의심)가 있어요. **잠금**은 상태가 아니라 따로 붙는 표시예요("만듦 + 잠금" 가능, v0.4).
  - 글·목소리·설정이 바뀌면 지문이 달라져 "오래됨"으로 표시돼요.
  - 넣기 메뉴는 그 줄 엔진이 받는 표기만 켜요.
  - 줄 아래에 글자 수·예상 소리 길이·예상 생성 시간(이 PC 측정 속도 기준)을 보여 줘요.
  - 불러오기: TXT·CSV(`이름: 대사`)는 MVP, MD·SRT·EPUB 은 v1. 대본도 CSV·TXT 로 내보낼 수 있어요. 키보드만으로 줄 이동·듣기·다시 만들기가 돼요.
- **미리 듣기·다시 만들기·테이크 비교(A/B)**
  - 줄마다 테이크 여러 개(씨앗을 바꿔)를 두고 고르기(고정)·이력(되돌리기)·잠그기(일괄 생성에서 건너뜀)를 해요.
  - **변형 N개 한 번에**: 2~6개를 만들어 나란히 듣고 골라요. 로컬이라 다시 만들기가 공짜인 점이 이 앱의 장점이에요(ElevenLabs 는 다시 만들 때마다 크레딧, 같은 입력 무료 재생성은 최대 2번).
- **일괄 생성 큐**
  - 범위: 전체·선택 줄·오래된 줄만·실패한 줄만·의심 줄만(MVP 는 길이·무음 검사가 켜졌을 때만 메뉴에 보임).
  - **엔진별로 묶어** 모델 바꾸기를 줄이고, 엔진의 묶음 크기·동시 요청 수에 맞춰 보내요. Qwen3 는 16개 묶음이 약 8배 빨랐고, 서버형 엔진은 동시 요청이 필요하고, Scenema 서버는 한 번에 하나만 받아요.
  - **CPU 엔진은 기본 4스레드**로 묶어요. Supertonic-3 이 CPU 를 다 쓰자 옆 GPU 엔진이 크게 느려졌어요.
  - 일시정지·재개·취소, **앱을 다시 켜도 이어서**(디스크 큐, 줄 단위 체크포인트), 실패한 줄만 다시. 진행률·남은 시간·지금 엔진·메모리를 보여 줘요.
  - **긴 글**은 엔진의 `max_chars` 와 측정한 안정 길이에 맞춰 문장 경계에서 나눠 만든 뒤 이어 붙여요.
- **허브 화면의 "빠른 시험" 칸**: 대본 없이 한 줄을 넣고 엔진·목소리를 골라 바로 들어요(허브만 쓰는 사용자용, MVP P0).

### 5.4 비교 모드("엔진 오디션")
oh-my-tts 벤치 경험을 사용자 기능으로 옮긴 것이에요.
- **고르기**: 내 대본 몇 줄 또는 **내장 문장 세트**(`common/sentences.yaml`, 장르 8개 51문장) × 엔진(·목소리) 여러 개.
- **만들기**: 줄 × 엔진 표로 만들어요. 엔진 설치·메모리 순서는 큐가 맞춰요.
- **블라인드 듣기**: 엔진 이름을 가리고 순서를 섞어 들어요. 장르마다 **자연스러움·발음·분위기 1~5 + 메모**를 남겨요(우리 사람 평가 방식).
- **기계 점수 칸**: 발음 오류율·환각·생성 시간·GPU 메모리·복제 닮음. **기계 자연스러움 점수(UTMOS 류)는 보여 주지 않아요** - 우리 벤치에서 사람 귀와 반대로 나왔어요.
- **결과**: 이름 공개 → 표·순위 → "이 엔진을 캐릭터에 쓰기". 보고서를 혼자 열리는 HTML·CSV·JSON 으로 내보내요. 자동 업로드는 없어요.
- 단계: 간단판(같은 줄을 엔진 2~4개로 나란히 + **이름 가리기 스위치·"이름 공개"**)은 MVP P1, 정식판(점수·51문장·보고서)은 v1.

### 5.5 품질 점검(받아쓰기로 다시 읽기)
- **MVP P1 - ASR 없는 검사**(v0.4): 길이가 예상의 2배를 넘거나 0.4배에 못 미치는 줄, 앞뒤 무음이 긴 줄, 소리가 거의 없는 줄을 "의심" 으로 표시해요. 모델을 더 받지 않아 가볍고, 벤치 환각 검사(`edges`)와 같은 기준이에요. 아래 ASR 점검은 v1 이에요.
- 만든 소리를 ASR 로 다시 받아써 **엔진 글(읽기 꼴)**과 비교해요. ASR 모델도 허브가 카탈로그로 받아요(역할 `asr`).
- **표시하는 것**
  - 발음 오류율이 높은 줄, 숫자를 다르게 읽은 줄
  - 대본에 없는 말이 앞·중간·끝에 끼어든 줄, 같은 말 반복, 잘림
  - 길이가 예상의 2배를 넘거나 0.4배에 못 미치는 줄, 앞뒤 무음이 긴 줄(벤치 환각 검사 `inserts`·`edges`)
  - 복제 줄에서 **목소리가 참조와 달라진 줄**(화자 닮음)
- **자동 다시 만들기**: 의심 줄을 씨앗을 바꿔 N번(기본 2번)까지 다시 만들고, 점수가 가장 좋은 테이크를 골라요. 로컬이라 공짜예요(ElevenLabs "Auto-Regenerate" 와 같은 생각).
- **ASR 엔진**: GPU 면 Qwen3-ASR-1.7B(벤치 표준), CPU 면 작은 모델(SenseVoice-Small 등, CPU 속도 측정 필요)이에요. Whisper 는 교차 확인용이에요(우리 측정에서 한국어 오류율이 더 높게 나왔어요: ZONOS3 3.9% vs Whisper 9.4%).
- **한계 표시**: 받아쓰기로는 된소리 같은 미세한 발음 차이를 못 잡아요. 발음은 사람 귀로 확인하라고 안내해요.

### 5.6 타임라인·여러 트랙 - 판단
- **MVP: 트랙 하나**(줄 순서 = 시간 순서). 줄 사이 쉼, 앞뒤 무음 자르기, 음량 맞추기만 해요.
- **v1: 배경음 트랙 하나 + 효과음**. 음악을 깔고 말할 때 음악을 줄여요(덕킹). 효과음 파일은 줄에 붙여요.
- **이후(P2): 줄 블록 타임라인**. voicebox Stories 처럼 끌어서 겹치게(대화 끼어들기).
- **하지 않음: 본격 다중 트랙 편집(DAW)**. 오디오북·팟캐스트는 트랙 하나로 충분하고, 유튜브는 영상 편집기에서 마무리해요. 줄별 파일·자막·캐릭터별 파일로 넘겨 주는 쪽이 더 쓸모 있어요.

### 5.7 내보내기
- **MVP 범위**(v0.4): 합친 WAV·MP3, 줄별 파일, SRT, 음량 2종, 만든 방법 기록, AI 생성 메타데이터. **FLAC·VTT·캐릭터별 파일·대본 CSV 는 v1** 이에요.
- **합친 파일**: WAV(엔진 표본율 그대로, 또는 48k·44.1k 로 맞춤)·MP3·FLAC.
- **줄별 파일**: `001_캐릭터_대사앞글.wav` 꼴. **자막**: SRT·VTT(실제 만든 길이 기준 시간, 읽기 지정한 줄은 원문으로).
- **캐릭터별 파일(스템)**, **대본 CSV**.
- **음량 기준**: 팟캐스트·유튜브(-16 LUFS), 방송(-23 LUFS)은 MVP. 오디오북 기준(ACX)·장 단위·M4B 는 v1.
- **만든 방법 기록**: 엔진·판·목소리·씨앗·설정·**쓴 엔진의 라이선스**를 JSON 으로 같이 줘요(4.11). 대본 글을 빼고 남기는 선택도 있어요.
- **파일 메타데이터**: "AI 생성 · Sori Studio · 엔진 이름"을 기본으로 넣어요(끌 수 있음, 7.6).

### 5.8 목소리 라이브러리와 복제 동의
| 종류 | 무엇 | 쓰는 엔진 |
|---|---|---|
| 엔진 기본 목소리 | 엔진에 딸린 목소리 + 샘플(한국어에 맞는 것을 앞에) | 그 엔진만 |
| **참조 목소리** | 클립 + 전사. **엔진을 넘어 공용** | 복제되는 엔진 전부 |
| **설계 목소리** | 묘사로 만든 뒤 **클립으로 고정** | 복제되는 엔진 전부 |

- **MVP 범위**(v0.4): 기본 목소리·참조 클립·설계 목소리(뽑기)·동의 기록. **전사는 손으로** 넣고(자동 전사는 ASR 이 오는 v1), 본인 목소리 동의는 동의 문장 녹음을 저장만 해요. **"본인 확인"(화자 닮음 비교)은 v1** - 화자 닮음 모델도 카탈로그로 받고 라이선스 동의를 거쳐요.
- **참조 클립 도구**: 녹음·올리기, 자르기(엔진별 권장 길이 표시: Confucius4 는 길수록 좋아짐 3초 0.69 → 18초 0.79, VoxCPM2 전사 없이 10초 0.74, Qwen3 10초 0.70), 잡음·음량 확인, **자동 전사 + 고치기**(전사가 필요한 엔진용).
- **엔진별 복제 방식 자동 선택**(측정 근거)
  - CosyVoice3: **전사를 빼고** 복제해요(빼야 오류율 1.2~1.3%).
  - Fish Drama-3: **전사 필수**예요(빼면 오류율 17%).
  - VoxCPM2: 전사가 있고 연기 지시가 없으면 전사 이어 말하기 방식으로 해요(닮음 0.81).
- **설계는 "뽑기"로 해요**: 같은 묘사라도 만들 때마다 목소리가 달라지고(VoxCPM2 카드도 인정), 한국어 묘사로는 성별 지정조차 잘 안 돼요(남성 묘사 6명 중 남자 음높이가 나온 수: VoxCPM2 0명, Qwen3 1명, Scenema 3명). 그래서 **후보 6개를 만들어 듣고 → 고르고 → 그 클립을 참조로 고정**해요(설계 클립을 참조로 쓴 닮음: VoxCPM2 0.73, Qwen3 0.75).
- **복제 동의**
  - **본인 목소리**: 화면에 나온 동의 문장을 읽어 녹음하면, 참조 클립과 같은 사람인지 화자 닮음으로 확인해 "본인 확인"으로 기록해요.
  - **권리가 있는 다른 목소리**: "녹음 당사자에게 허락을 받았어요" 확인 + 출처 메모를 받아요(앱이 검증할 수는 없어 기록만).
  - 로컬에서 만드는 것 자체는 막지 않아요(voicestudio 와 같음). **목소리 묶음 내보내기·공유에는 동의 기록이 필요해요.**

## 6. LLM 층(로컬 우선, 선택)

### 6.1 연결
- **MVP(P1)**: 사용자가 이미 쓰는 **로컬 LLM 서버**에 OpenAI 호환으로 붙어요. Ollama(`http://127.0.0.1:11434/v1`)·LM Studio·llama.cpp 서버가 여기에 들어가요.
- **v1**: **허브가 LLM 도 카탈로그로 관리**해요(역할 `llm`). 한국어 대본 일에 맞는 작은 GGUF 모델을 우리가 시험해 추천하고, llama.cpp 서버를 허브가 받아 띄워요. 사용자가 Ollama 를 따로 깔 필요가 없어져요. 어떤 로컬 LLM 이 맞는지는 **아직 측정 안 함**이에요.
- **원격 LLM**: 사용자가 주소·키를 **직접 넣을 때만** 붙어요. 우리가 기본 목록·추천을 넣지 않아요. 붙으면 "이 대본이 ○○ 서버로 보내져요"를 표시해요.
- **기능별 연결**: 쓰임새마다 다른 모델을 고를 수 있어요(voicestudio 방식). "연결" 단추는 실제 답을 받아 본 뒤에만 켜요. 키는 OS 키체인에 둘 계획이에요.

### 6.2 원칙
1. **LLM 이 없어도 모든 기본 기능이 돼요**(규칙 대체가 있거나 수동으로).
2. **제안만, 적용은 사용자**: 바뀐 곳을 표시해 보여 주고 "적용·하나씩 적용·버리기"를 고르게 해요.
3. **구조화된 답**: JSON 스키마로 받아 검사해요. 줄 정리처럼 글이 바뀌면 안 되는 일은 **원문 글자가 바뀌었는지 비교**해 경고해요.
4. **찌꺼기 제거**: 생각 태그·마크다운이 대본에 섞여 들어가지 않게 지워요(pyvideotrans 사용자 불만에서 얻은 교훈).

### 6.3 쓰임새
| 쓰임새 | 하는 일 | 입력 → 출력 | LLM 없을 때 | 단계 |
|---|---|---|---|---|
| **대본 정리** | 붙여 넣은 글을 줄로 나누고 화자 배정 | 글 → `[{화자, 대사}]` | 규칙(`이름: 대사`·따옴표·줄바꿈·문장 길이) | MVP P1 |
| **연기 제안** | 줄마다 감정·세기·비언어 위치(**그 엔진이 받는 것만**) | 줄 + 엔진 `caps` → 제안 목록 | 수동 | MVP P1 |
| 대본 쓰기·다듬기 | 주제·길이·말투로 초안, 구어체로, 길이 맞추기 | 지시 → 대본 줄 | 없음 | v1 |
| **발음 제안** | 엔진이 틀리기 쉬운 곳(숫자·영어·한자어·뜻에 따라 갈리는 말, 예: 잠자리) 찾기 | 줄 → `[{위치, 원문, 읽기, 이유}]` → 승인하면 읽기 지정·사전으로 | 규칙 다듬기만(5.1) | v1 |
| 번역 대본 | 줄 단위 번역, 원래 길이에 맞춤, 용어집 | 줄 + 목표 언어 → 번역 줄 | 없음 | v1 |
| **캐스팅** | 인물 설명 → 엔진을 넘어 목소리 후보 3개 + 이유 | 인물 설명 + 목소리 메타 → 후보 | 규칙 점수(같은 입력이면 같은 결과 - 운영하며 써 본 방식) | v1 |
| 성격대로 다시 쓰기 | 캐릭터 성격·말투로 대사 바꾸기(voicebox) | 대사 + 성격 → 대사 | 없음 | 이후 |
| 점검 해설 | 받아쓰기 차이를 사람 말로 | 원문·받아쓴 글 → 설명 | 차이 표시만 | 이후 |

### 6.4 자동 흐름("이 글을 두 사람 팟캐스트로 만들어 줘", 이후)
- 단계: 계획 → 대본 → 캐스팅 → 연기 제안 → 생성 → 품질 점검 → 다시 만들기 → 내보내기.
- 단계마다 결과가 **보통 프로젝트 자료**(대본 줄·캐릭터·테이크)로 남아 사람이 이어서 고칠 수 있어요. 멈출 지점을 고를 수 있어요(단계마다 확인 / 끝까지 자동).
- 시간 예산(원격 LLM 을 붙였다면 토큰 예산도)을 시작 전에 보여 주고, 넘으면 멈춰요.
- 상용에도 같은 흐름이 있어요(ElevenLabs Studio Agent 가 프롬프트로 초안을 만듦).

### 6.5 MCP(이후 P2)
- **허브 = MCP 서버**: Claude Code 같은 에이전트가 내 PC 의 엔진으로 말하게 해요(`list_engines`·`list_voices`·`speak`·`render_project`). 공통 API(4.9) 위에 얇게 얹어요.
- **스튜디오 안 에이전트 = MCP 클라이언트**: 자동 흐름이 외부 도구(자료 찾기 등)를 쓰게 해요.

## 7. 배포 형태

### 7.1 데스크톱 앱 vs 로컬 웹 화면 vs 둘 다 → **둘 다(화면은 한 벌)**
| 형태 | 장점 | 단점 |
|---|---|---|
| 데스크톱 앱만 | 설치 파일·아이콘·파일 끌어 놓기·자동 업데이트·서명 | 다른 PC·서버의 GPU 를 못 씀 |
| 로컬 웹 화면만(TTS-WebUI 식) | 원격 GPU·도커·연구자에게 좋음 | 일반 사용자는 설치가 어려움(파이썬·명령줄) |
| **둘 다** | 크리에이터는 설치 파일로, 연구자·원격 GPU 는 serve 모드로 | 껍데기 한 겹 더(화면은 같은 것) |

- **추천: 허브 서버 + 웹 화면 한 벌 + 데스크톱 껍데기.** voicestudio·voicebox·TTS-WebUI 모두 "파이썬 서버 + 웹 화면"으로 같은 결론이에요.
- **껍데기는 Electron 추천**(열린 질문 4)
  - 크롬 엔진이 함께 들어가서 운영체제마다 오디오 재생·녹음·파일 처리가 같게 동작해요.
  - voicestudio 는 Tauri(운영체제 내장 WebView)에서 Electron 으로 옮겼어요. 그 전 변경 기록에 WebView 차이로 생긴 고장(리눅스 빈 창, 맥 12 시작 실패, WKWebView 오디오 제약)이 여럿 있어요(옮긴 이유로 추정).
  - 껍데기 크기(약 100MB 대, 추정)는 엔진 하나가 수 GB 인 것에 비하면 작아요.
- **허브 기본 포트 5150**(v0.4): 쓰이고 있으면 다음 빈 포트를 쓰고 껍데기·화면에 알려요. serve 모드의 프로젝트 폴더는 **허브 PC** 에 있어요(브라우저는 화면만).
- **serve 모드**: `sori-studio serve --host 0.0.0.0` 으로 GPU 상자·클라우드 GPU 에서 허브를 띄우고, 노트북의 데스크톱 앱이나 브라우저가 붙어요(토큰 필요, HTTPS 또는 사설망 권장). 리눅스 서버용 도커 이미지(허브 통째)는 v1 P2 예요.

### 7.2 설치 경험(첫 실행)
1. **서명된 설치 파일 하나**(Windows 먼저). 공식 내려받기는 GitHub Releases 한 곳 + 해시 공개.
2. **첫 실행 마법사**
   1. 시스템 점검(4.5)
   2. 모델 폴더 고르기(드라이브·빈 공간)
   3. 쓰임새 고르기: 나레이션·오디오북 / 연기·드라마 / 내 목소리 / GPU 없음 → **추천 엔진 1개 + 대안**(4.3, 라이선스 배지 함께)
   4. 설치 계획 → **라이선스 동의** → 설치
   5. 자가 시험 소리 듣기
   6. 업데이트 확인 켜기(기본 켬, 4.7)
   7. 예제 프로젝트(두 사람 대화 짧은 대본) 열기
3. **공통 런타임은 작게**(허브 서버·오디오 도구·한국어 다듬기·Kiwi). 엔진 환경은 그 엔진을 고를 때 받아요.
4. **GPU 없는 PC 도 바로**: Supertonic-3(CPU)로 시작할 수 있어요.
5. 첫 실행 목표(추정, 측정 전): NVIDIA 8GB 깨끗한 Windows PC 에서 설치부터 첫 소리까지 30분 안(100Mbps 회선, 모델 받기 포함).

### 7.3 오프라인
- 설치가 끝나면 엔진·로컬 LLM·한국어 다듬기·품질 점검·내보내기가 모두 인터넷 없이 돼요.
- 오프라인인데 모델을 다시 받으려 하지 않게, 설치된 것만으로 시작해요(voicebox 사용자 불만 상위권).
- 회사·학교망에서는 **사용자가 자기 PC 에 설치된 엔진을 다른 PC 로 옮기는 내보내기**가 이후 P2 예요(우리가 배포하는 꾸러미가 아니고, 라이선스가 허락하는 엔진만).

### 7.4 앱 라이선스 추천: **Apache-2.0**
- **이유**
  - 목적이 "오픈소스 허브·스튜디오를 널리 쓰게" 하는 것이고 앱을 팔지 않아요 → 상용 이중 라이선스(voicestudio 의 AGPL + CLA 모델)가 필요 없어요.
  - 개인·회사 누구나 부담 없이 쓰고 고칠 수 있어요. **특허 허락 조항**이 있어 음성 기술 분야에서 MIT 보다 안전해요.
  - MIT·Apache 코드(voicebox·TTS-WebUI·GPT-SoVITS·Speaches 등)를 출처 표시로 가져올 수 있어요.
  - 기여 받기가 쉬워요(CLA 대신 DCO - 커밋에 서명 한 줄).
- **대안 AGPL-3.0**: 누가 허브를 고쳐 닫힌 서비스로 내는 것을 막고 싶을 때. 대신 채택이 줄고 기업 사용이 어려워져요.
- **주의**
  - voicestudio(AGPL)·AllTalk(AGPL)·pyvideotrans(GPL) **코드는 복사하지 않아요**(아이디어만).
  - 이름·로고 사용 규칙은 8.2 에서 다뤄요.
  - 모델 가중치 라이선스는 앱 라이선스와 별개예요(4.11).

### 7.5 신뢰 원칙
1. **계정·키 없이 모든 기능**이 돼요.
2. **텔레메트리 없음**(익명 통계도 없음). 오류 보고는 사용자가 내용을 보고 미리 채운 GitHub 이슈로 직접 보내요.
3. 네트워크는 사용자가 누른 일만 해요(모델·엔진 받기, 업데이트 확인, 사용자가 넣은 원격 LLM). **호출 목록을 문서와 설정 화면에 공개**해요.
4. 키·토큰은 지금은 사용자 폴더(Windows `%LOCALAPPDATA%/SoriStudio`, 그 밖 `~/.sori-studio`)의 파일에 두고(macOS·리눅스는 본인만 읽기 0600), OS 키체인은 원격 LLM 키를 넣을 때 함께 옮겨요. 화면 코드·로그·내보내기 파일·오류 보고에는 넣지 않아요.
5. **서명된 설치 파일**과 해시를 공개하고, 공식 내려받기는 한 곳이에요. README·설치 화면에 "공식이 아닌 '고침 도구'를 받지 마세요"를 적어요(voicestudio 에 가짜 설치 고침 미끼 이슈가 여럿 올라왔어요).
6. 엔진 설치는 남의 코드를 실행하는 일이에요. 공식 출처·커밋·라이선스를 보여 주고 동의를 받고, 엔진별로 격리하고, 관리자 권한은 쓰지 않아요.
7. 사용자 파일은 사용자가 고른 폴더에만 둬요.

### 7.6 윤리: 복제 동의·AI 생성 표시
- 복제 동의는 5.8 에서 다뤄요.
- **AI 생성 표시**: 내보낸 파일 메타데이터에 "AI 생성"을 기본으로 넣어요. **비가청 워터마크**(AudioSeal)는 기본 켬 + 끌 수 있게를 추천해요(열린 질문 11). 엔진 라이선스가 표시·워터마크 유지를 요구하면(Fish Drama-3 "워터마크 제거 금지") 그 엔진 결과에서는 끌 수 없게 해요.
- 갤러리·예제에 실존 인물 목소리를 넣지 않아요.
- 국내 AI 생성물 표시 규정이 이런 로컬 오픈소스 앱 배포자에게 걸리는지는 **확인하지 않았어요**(열린 질문 13).

## 11. 한계(이 설계서가 확인 못 한 것)
- 엔진 측정은 **2026-11-16 벤치 한 번**(씨앗 3, 우리 문장 세트)이고, 사람 평가는 **사용자 한 명**의 귀예요.
- **실제 개인 PC 는 재지 않았어요**: 메모리는 클라우드 GPU 실측으로 "들어가는 카드"를 판정했어요. **Mac 칸은 모두 미검증**이에요. AMD·CPU 전용 PC 의 실제 속도는 몰라요. Qwen3-TTS 한 판·한 건 메모리도 다시 재야 해요.
- 감정 반영률은 감정 인식기(SenseVoice)가 한국어 감정을 잘 못 가려서(우리 기준선 맞힘 26%) **상대 비교로만** 의미가 있어요.
- 한국어 대본 일에 맞는 로컬 LLM, CPU 용 ASR 의 한국어 정확도·속도는 측정 전이에요.
- 엔진들의 유지보수 상태는 Supertonic-3 말고는 확인하지 않았어요.
- 이름은 GitHub 저장소·계정과 PyPI 만 봤고, 상표·도메인·앱스토어는 안 봤어요.
- python.org 임베드용 파이썬의 서명 여부는 확인이 필요해요.
- Electron 추천의 근거 중 "voicestudio 가 WebView 문제로 옮겼다"는 변경 기록을 보고 한 추정이에요.
- 감시 시간 한도·여유 비율 같은 숫자는 처음 값이에요(시험으로 조정). 일정·인력 추정은 넣지 않았어요.
